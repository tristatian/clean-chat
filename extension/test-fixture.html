How does Spotify's PKCE login work?

What PKCE is for

PKCE lets an app that cannot keep a secret, such as a static web page, run the OAuth authorization-code flow safely. Instead of a client secret, the app proves it started the login by presenting a one-time secret it generated itself.

The four steps

  1. Generate a random code_verifier, hash it with SHA-256, base64url-encode the digest. That is the code_challenge.
  2. Send the user to the authorize endpoint with the challenge. Keep the verifier in sessionStorage.
  3. The user approves and is redirected back with a short-lived code.
  4. POST the code plus the original verifier to the token endpoint. Spotify hashes the verifier and compares.
POST /api/token
grant_type=authorization_code&code=…&code_verifier=…

Why it is safe

An attacker who intercepts the code cannot redeem it, because they never saw the verifier. SHA-256 cannot be reversed to recover it from the challenge.

What happens after the token expires?

Access tokens expire after one hour. Use the refresh token to get a new one without sending the user through login again. For PKCE clients Spotify returns a new refresh token with each refresh, so always store the newest one.
