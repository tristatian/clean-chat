Why does a static site need PKCE if there is no client secret to steal?

What PKCE protects

PKCE binds the authorization code to the app instance that started the login. The app proves it with a one-time verifier it generated itself.

  • Generate a random verifier and send its SHA-256 hash with the authorize request.
  • Keep the verifier in the browser.
  • Trade the returned code plus the verifier for tokens.

An attacker who intercepts the code cannot redeem it without the verifier.

What happens when the access token expires?

Access tokens last about an hour. Use the refresh token to get a new one without another login, and store the newest refresh token each time.

POST /api/token
grant_type=refresh_token&refresh_token=…
